## Context

הבדיקה נשאלה כשאלה אחת: **כמה נוח ואינטואיטיבי להגדיר את התקשורת עם ההורים, וכמה נוח לתקשר בפועל** — בשני הערוצים (WhatsApp והפורטל) ומשני הצדדים (הצוות וההורה).

התשובה הקצרה: **ה"לתקשר" עובד היטב. ה"להגדיר" הוא שנשבר.**

הצד השוטף — הודעה מהורה שמגיעה לדשבורד, תשובה שחוזרת לפורטל, פולינג חי, דיאלוג ביטול שמציג סכום חיוב אמיתי, חסימת שליחה מחוץ לחלון 24 השעות עם הסבר — כל אלה עברו עם ראיות (ר' "מה עבר"). לעומת זאת, מסכי ההגדרה מכילים פקד מרכזי אחד שמעולם לא עשה דבר, וכשל חיבור שלם שלא מיוצג בשום מקום ב-UI.

## הממצא המרכזי

### F1 · שעות התזכורת שההורה אמור לקבל — פקד מת [Critical]

**שכבה:** Architecture · **משטח:** `/settings/reminders` (1440×900, he) + `/onboarding` · **פרסונה:** בעלת סטודיו

**שחזור**
1. היכנס כבעלים ל-`/settings/reminders`.
2. תחת "שעות לפני שיעור" בחר **48 שעות לפני**. הטקסט המסביר מבטיח במפורש: *"ההורה יקבל הודעת WhatsApp X שעות לפני תחילת השיעור"*.
3. לחץ "שמור" → מופיע אישור הצלחה.
4. רענן → הערך 48 נשמר ומוצג.
5. `select lesson_reminder_hours from organizations` → **48**.

**מה קורה בפועל**
`supabase/functions/lesson-reminders/index.ts:76` קורא:
```ts
org.automation_lesson_reminder_hours ?? org.lesson_reminder_hours ?? 24
```
ו-`supabase/migrations/20260514000001_automation_toggles.sql:10-11` מגדיר:
```sql
ADD COLUMN IF NOT EXISTS automation_lesson_reminder_hours int NOT NULL DEFAULT 24
  CHECK (automation_lesson_reminder_hours IN (2, 12, 24));
```

העמודה היא `NOT NULL DEFAULT 24` — כלומר ה-`??` **לעולם לא נופל** ל-`lesson_reminder_hours`. אומת מול ה-DB החי: `is_nullable = NO`, `column_default = 24`.

**המשמעות המלאה, בשלוש שכבות:**

1. **`lesson_reminder_hours` היא עמודה מתה עבור כל ארגון** — גם ארגון שמעולם לא פתח את `/settings/whatsapp`. אין מצב שבו הערך שנשמר במסך "תזכורות" משפיע על מתי תישלח תזכורת.
2. **48 ו-4 בלתי-אפשריים בכל דרך.** ה-CHECK במסד מתיר רק `(2, 12, 24)`, וה-Zod ב-`automations-actions.ts:17` מאמת `[2, 12, 24]`. מסך התזכורות מציע חמש אפשרויות — `[2, 4, 12, 24, 48]` — מהן שתיים נדחות ברמת המסד.
3. **אשף ההצטרפות כותב לעמודה המתה.** `src/app/(onboarding)/onboarding/actions.ts:128,149` שומר `lesson_reminder_hours` בלבד. כל סטודיו חדש עובר צעד ייעודי של הגדרת תזכורות — לתוך שדה ששום דבר לא קורא.

**מה שהיה צריך לקרות:** או שהערך מהמסך "תזכורות" משפיע, או שהמסך לא מציג את הפקד.

**הערה חשובה על הכיוון:** הקדימות של `automation_lesson_reminder_hours` היא **החלטה מכוונת** (`docs/sprint-31-scope.md:72`) — Sprint 31 העביר את הבעלות על העיתוי למסך האוטומציות. הבאג אינו ב-Edge Function; הבאג הוא שהמסך המפסיד נשאר עומד, עם ניסוח מבטיח, עם אפשרויות שאינן קיימות, ועם אשף הצטרפות שממשיך להזין אותו.

### F4 · שליחה שנכשלת מוחקת את הטקסט שהוקלד [High]

**שכבה:** Feedback · **משטח:** `/messages/whatsapp/[phone]`, `/messages/[studentId]` · **פרסונה:** בעלת סטודיו

**שחזור**
1. פתח שרשור WhatsApp עם חלון 24 שעות פתוח.
2. הקלד תשובה אמיתית (נבדק: 90 תווים על חיוב כפול).
3. לחץ "שלח" כשהשליחה תיכשל (טוקן פג / תקלת רשת).

**נצפה** "שליחת ההודעה נכשלה" באדום — **ותיבת הכתיבה ריקה.** הטקסט אבד. בעלת הסטודיו מקלידה מחדש מהזיכרון.

**המנגנון — וזה החלק המעניין**
המפתחים כתבו שמירה מפורשת בדיוק נגד זה:
```tsx
useEffect(() => { if (state.error === null) formRef.current?.reset() }, [state])
```
(`WhatsAppThread.tsx:42`, `DashboardMessageThread.tsx:26`)

אבל הטופס הוא `<form action={serverAction}>` עם `<input name="body">` לא-מבוקר, ו-React 19 **מאפס טפסים לא-מבוקרים אוטומטית** בסיום כל form action, ללא קשר לתוצאה. ההגנה שנכתבה מנוטרלת על ידי ברירת המחדל של הפריימוורק.

**היקף מדויק (אחרי אימות)**
- `WhatsAppThread.tsx` ו-`DashboardMessageThread.tsx` — **הטקסט אובד לחלוטין**, אין גיבוי.
- `PortalMessageThread.tsx:98-106` — כאן יש גיבוי ל-`sessionStorage` בכל הקשה, אבל השחזור רץ ב-mount בלבד. אחרי כשל התיבה **נראית ריקה** ושום דבר לא מרמז שרענון היה מחזיר את הטקסט. ההורה מניח שהטקסט אבד.

## Phase 7ג — F2 ו-F4 תוקנו ואומתו (4.9.2026)

### F2 — כשל חיבור Meta הפך לגלוי

`loadStatusesWithCatchUp` הפסיקה לבלוע את הכשל ומחזירה עכשיו `{ rows, lookupFailed, notConnected }`. העמוד מציג באנר ענבר עם קישור להגדרות WhatsApp, ו-`resolveTemplateApproval` קיבלה פרמטר `statusesVerified`: כשלא הצלחנו להגיע ל-Meta, תבנית ללא רשומה מדווחת **`UNKNOWN`** ("לא ידוע — יש לרענן סטטוסים") במקום `PENDING`. הצ'יפ `UNKNOWN` נוסף ל-`STATUS_STYLES` כדי שיוצג מתורגם ולא כמילה גולמית.

| בדיקה | לפני | אחרי |
|---|---|---|
| באנר שמסביר שהחיבור נפל | ✗ | ✓ + קישור להגדרות |
| צ'יפים "ממתין לאישור" | **9** | **0** |
| צ'יפים "לא ידוע — יש לרענן סטטוסים" | 0 | **9** |
| דליפת המילה הגולמית `UNKNOWN` | — | ✗ (מתורגם) |
| axe בעמוד | — | 0 הפרות |

שני טסטים חדשים ב-`templateApprovalView.test.ts` נועלים את ההתנהגות: כשל חיפוש → `UNKNOWN`, אבל **פסיקה אמיתית של Meta שנשמרה נשארת בתוקף** גם אם חיפוש מאוחר יותר נכשל.

### F4 — טקסט שנכתב שורד שליחה כושלת

שלושת ה-composers הפכו לקלטים מבוקרים, והניקוי קורה רק כשהשליחה הצליחה. במקום אפקט, ההתאמה נעשית **בזמן רינדור** — `useActionState` מחזיר את אותו אובייקט עד שפעולה נפתרת, כך שזהות שהשתנתה היא הסימן היחיד האמין ששליחה נסגרה.

| משטח | תרחיש הכשל שנבדק | תוצאה |
|---|---|---|
| `WhatsAppThread` | כשל Meta אמיתי (טוקן לא תקף) | שגיאה מוצגת · **הטקסט נשמר** |
| `PortalMessageThread` | ה-JWT של הפורטל פג בזמן שהעמוד פתוח | שגיאה מוצגת · **הטקסט נשמר** |
| `DashboardMessageThread` | הודעה של 2134 תווים מעל מגבלת 2000 | שגיאה מוצגת · **2134 התווים נשמרו** |
| כל השלושה | שליחה תקינה | ההודעה נשלחה · התיבה התנקתה |

**ובדרך התגלה שגיבוי הטיוטה בפורטל מעולם לא עבד.** אפקט הניקוי רץ גם ב-mount (המצב ההתחלתי הוא `{ error: null }`, שנקרא כמו "שליחה הצליחה") ומחק את הטיוטה מ-`sessionStorage` **לפני** שאפקט השחזור הספיק לקרוא אותה. אומת: הורה מקליד, מרענן, והטקסט חוזר — מה שלא קרה קודם.

### שתי טעויות בדרך, שתיהן נתפסו באימות

1. **ההגנה הראשונה נשרפה ב-StrictMode.** השתמשתי ב-`useRef` כדגל "ריצה ראשונה", אבל StrictMode מריץ אפקטים פעמיים ב-mount — הריצה הראשונה שרפה את הדגל והשנייה מחקה את הטיוטה בכל זאת. הוחלף בהשוואת **זהות** מול המצב ההתחלתי, שהיא יציבה.
2. **הרפקטור לרינדור שבר את מחיקת הטיוטה.** דגל שנגזר בזמן רינדור לא מגיע לאפקט: עדכון state בזמן רינדור מבטל את הרינדור ומריץ אותו מחדש, והדגל חוזר ל-false. הוחלף במונה ב-state אמיתי, שכן מגיע ל-commit. נתפס כי `draft removed` ירד ל-false באימות החוזר.
