# scripts/

Operational tooling, run by hand from the repo root. None of these are wired
into `package.json` — invoke them with `npx tsx scripts/<name>.ts`. Most read
credentials from the environment, falling back to `.env.local`.

Spent one-off scripts live in [`archive/`](archive/README.md).

## Demo tenants

Each tenant has a paired seed and cleanup script and its own deterministic UUID
prefix, so the two never collide.

| Script | Tenant |
| --- | --- |
| `seed-review-demo.ts` / `cleanup-review-demo.ts` | "Brightpath Tutoring", the English tenant Meta App Review logs into (`d2000000-`) |
| `seed-video-demo.ts` / `cleanup-video-demo.ts` | "סטודיו מיכל למוזיקה", the Hebrew tenant used to film marketing video (`d3000000-`). Local-only unless `VIDEO_DEMO_ALLOW_REMOTE=1` |

Both seeds build a populated org from nothing — auth users, teachers with
availability, parents, students, ~14 weeks of lessons, four months of billing
run through the real engine, homework, notes and goals.

## WhatsApp provisioning

| Script | What it does |
| --- | --- |
| `whatsapp-number-setup.ts` | Registers a real phone number on the Lessio WABA and connects it to an org. Five subcommands (`list`, `add`, `request-code`, `verify`, `register`, `connect`) because SMS verification and the prod write are interactive. The manual path that bypasses Embedded Signup |
| `connect-org-whatsapp.ts` | Connects any org to a business number using the shared System User token. The pilot-phase path, where customer numbers sit on Hadar's own WABAs and there is no Embedded Signup token |
| `connect-demo-whatsapp.ts` | Same, but specific to Meta's test number, whose token is generated by hand |
| `meta-precheck-calls.ts` | Generates the Graph traffic App Review's `api_precheck` step needs before it will pass. Still required — the review has not been submitted |

## Diagnostics (read-only)

| Script | What it does |
| --- | --- |
| `check-stored-whatsapp-token.ts` | Decrypts and `debug_token`s the token production actually sends with (`organizations.whatsapp_access_token`), not the one in `.env.local`. Use this when the bot receives messages but silently fails to reply |
| `diagnose-demo-whatsapp.ts` | End-to-end wiring check for the demo test number. Hardcodes the demo phone-number-id, so it is demo-specific |

## SQL

`setup-crons.sql` registers the Edge Function schedules via `pg_cron` + `pg_net`.
Substitute `PROJECT_REF_PLACEHOLDER` and `SERVICE_KEY_PLACEHOLDER` before
running. The cron each function expects is documented in `supabase/config.toml`
(the `schedule` key is unsupported on CLI v2.x, so schedules are registered
here or in the Dashboard, never by the CLI).
